# General processing hardening — work in progress

**Not release-ready. Do not merge or publish this branch.**

Baseline: `7f8fdd025fcc2db5467067dedc58b28628cefdf4` (`v0.2.25`).
This checkpoint changes automatic memory processing, not just email handling.
The package version intentionally remains unchanged on the development branch;
no replacement of the published 0.2.25 artifacts is intended.

## Implemented in this checkpoint

- Source-neutral evidence units and a shared automatic-candidate admission
  boundary; assistant synthesis and retrieved memory cannot independently
  authorize a new write.
- Bounded, redacted current-turn call/result provenance through capture/inbox,
  MCP, Hermes and Codex. Legacy metadata without observed content grants no
  content authority; truncated observations are explicitly unresolved.
- Removal of counted-repair/email-specific post-Gate candidate injection.
- Candidate-local scope checking, pending-summary exact deduplication and
  same-turn update-target conflict detection.
- Optional strictly validated per-unit Gate coverage. Missing coverage is
  retained as deferred evidence, not treated as complete extraction.
- Immutable write-intent metadata and a pending-operation journal; processed
  index rebuilding preserves that journal. The injected final-ledger-failure
  regression keeps the actual UPDATE disposition after replay.
- 22 new tests spanning ordinary dialogue, mixed assertion/query turns,
  examples, third-party ownership, six tool categories, provenance isolation,
  duplicate writes, incomplete evidence, unknown sections and replay.

## Actual validation (Linux, Python 3.13)

- Focused suite: **52 tests passed** (22 new tests, 20 admission-noise tests,
  and 10 existing todo-state-recovery tests).
- Complete suite, executed in 50 bounded module groups: **633 tests**;
  **39 modules passed, 11 modules failed; 33 reported failures and 19 errors;
  4 platform/optional tests skipped**. Subtest failures are runner counts,
  not a claim about the number of unique failing methods.

## Remaining work / limitations

1. Finish classifying every failing regression; improve genuinely grounded
   elliptical/paraphrased evidence handling and update only obsolete fixtures
   without weakening write-boundary assertions.
2. Complete source-neutral bounded coverage correction and distinct evidence-
   versus candidate-level accounting. Candidate-only legacy Gate output is
   still accepted conservatively with unresolved evidence retained.
3. The current syntax/lexical admission fallback is not a universal semantic
   classifier. Mixed quotation/example contexts, arbitrary paraphrases,
   multilingual input and ambiguous scopes need broader adversarial tests.
4. TurnPlan currently freezes write-intent metadata, not the entire finalized
   summary payload. Finish journal validation, competing-target semantics and
   scope-correction special-path coverage before claiming one uniform commit
   path. This is forward recovery, not an all-Vault filesystem transaction.
5. Finish overflow/retention checks and host-format compatibility for generic
   tool evidence; large results deliberately defer rather than silently become
   complete evidence. No arbitrary additional tool call is executed by memleaf.
6. Implement the proposed read-only audit/dry-run facilities and their
   compatibility tests; they are not present in this checkpoint.
7. Full Linux/Windows/macOS CI, package acceptance, independent diff review,
   then a separately approved release commit. Main and published artifacts
   must remain unchanged until the gates pass.

Retrieval visibility, shared-Vault ownership, scope-map/search/read protocol and
independent model routing are not intentionally changed. That statement is
scope of work, not a substitute for regression verification.
