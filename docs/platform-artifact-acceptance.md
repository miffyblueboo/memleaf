# Installed-artifact and native Core validation (G5b)

The CI builds one wheel and source distribution on Ubuntu/Python 3.12, then
verifies those same bytes on Ubuntu (Python 3.11/3.12/3.13), Windows (3.12) and
macOS (3.12). This is deliberately not the Cartesian product of all interpreters
and operating systems. All matrix entries gate the existing Release job. The
original release-subject and main-branch conditions remain: ordinary development
commits neither create a release nor publish to PyPI.

`scripts/verify_distribution.py --prepare` binds package code, Provider resources,
public tests, packaged acceptance fixtures, project metadata and artifact SHA-256
to the CI commit. Verification refuses mismatching artifacts, missing/extra code,
missing tests, changed fixtures and another commit before installation. A checksum
manifest binds observation; it is not a signature against replacement of the
manifest and the source together. The build, checkout and workflow remain trusted
CI inputs.

For each matrix entry the verifier creates separate fresh virtual environments
for the original wheel and a wheel rebuilt natively from the sdist. The rebuild
uses developer build tools; Memleaf's runtime dependency list is unchanged.
Installation uses `--no-index --no-deps`; the native build uses `--no-index
--no-deps --no-build-isolation`. No application is installed in the developer's
normal Python environment. The copied test workspace contains tests, examples
and the verification script, **not src/memleaf**. `-I`, removal of PYTHONPATH/
PYTHONHOME and an import-prefix assertion guard against accidentally testing the
checkout, user site or an editable package. Entry-point and distribution versions
must agree with project metadata. Source/sdist/installed tests must be evaluated
as separate observations, not multiplied into a larger independent test count.

The summary identifies artifact hashes, CI commit, OS, interpreter, test counts,
failures/errors and every skipped test/reason. Zero tests, inconsistent counts or
any failure is a gate failure. A successful suite containing explicit skips is
reported `passed_with_skips`; platform-dependent POSIX-only checks do not become
Windows evidence. Logs survive failures in their own per-platform artifact.
No caller model configuration or real Vault is accepted. Semantic acceptance and
actual Hermes installation remain `not_run`, and switch_authorized remains false.

New native Core regressions use real subprocesses to check mutual exclusion and
lock-holder termination, UTF-8 file paths/content, and an actual MCP stdio process
with Chinese captured messages. No assistant is generated by a model; the protocol
messages are synthetic fixtures. Atomic-replacement I/O failure is fault injection,
not proof of every disk-full or power-loss behavior. Existing subprocess recovery,
source-revision, query, Forget and backup tests run against both installed forms.

Run from a complete checkout after building the two distributions:

```sh
python scripts/verify_distribution.py --prepare --source . --dist dist --commit <tested-commit>
python scripts/verify_distribution.py --verify --source . --dist dist --commit <tested-commit> --output new-platform-report
```

The output directory must be new. This developer tool creates and removes its own
temporary environments; it does not change process/remember defaults, start an
Agent, stop a user's processes, restore a backup or authorize migration. Actual
Flash repetitions and a held-out corpus, real Hermes/Provider installation and
upgrade behavior, Windows ACL verification and production migration remain
separate acceptance gates. Local Linux success is never reported as Windows or
macOS execution. No prompts, model call budgets or package version are changed.
